# DM Download System v3.2.0 规划方案 (草案)

## 1. 目标
在 v3.1.0 "薄壳" 的基础上，进一步提升桌面端集成度，实现 "半编排" 架构。主要解决数据库捆绑、子进程自动化管理及离线分发问题。

## 2. 核心任务

### 2.1 MariaDB 捆绑与自动化部署 (v3.2.1 提前规划)
- **目标**: 用户无需预装 Docker 或 MariaDB，双击即可运行。
- **方案**:
  - 引入 `mariadb-bin` 跨平台二进制包。
  - Electron 启动时检查本地数据目录，若无数据库则初始化。
  - 实现数据库进程的生命周期管理 (Spawn/Kill)。

### 2.2 API 进程编排 (Orchestration)
- **目标**: 壳进程统一管理后端服务，消除手动启动多个 Dev Server 的需求。
- **方案**:
  - Electron 主进程使用 `child_process.spawn` 启动 API 进程。
  - 实现进程间的健康检查机制，确保后端就绪后再加载前端窗口。
  - 统一日志输出到 Electron 控制台或本地日志文件。

### 2.3 静态资源服务优化
- **目标**: 摆脱对 3000/3100 端口的依赖。
- **方案**:
  - 生产环境下，壳进程使用 `electron-serve` 或自定义协议加载 `web` 和 `gm-admin` 的打包产物。
  - API 地址动态注入到前端 (通过 IPC 或全局变量)。

### 2.4 打包与分发
- **工具**: 使用 `electron-builder` 进行打包。
- **功能**:
  - 支持 Windows (NSIS), macOS (DMG), Linux (AppImage)。
  - 实现自动更新机制 (Auto-update)。
  - 代码签名 (Code Signing)。

## 3. 技术挑战
- **跨平台二进制兼容性**: 尤其是 MariaDB 和 FFmpeg 的路径处理。
- **进程僵死处理**: 确保壳进程崩溃时，所有子进程 (API, MariaDB, Worker) 都能正确退出。
- **性能开销**: 优化主进程启动速度，减少内存占用。

## 4. 进度计划
- **Phase 1**: API 编排与静态加载 (预计 2 周)。
- **Phase 2**: 数据库捆绑与初始化 (预计 2 周)。
- **Phase 3**: 打包分发与自动更新 (预计 1 周)。
