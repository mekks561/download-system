# Resource Governance Center Design (2026-10-13)

## 1. 概述 (Overview)
资源治理中心是 GM 管理后台的核心功能模块，旨在为管理员提供全局存储资源的监控、分析与自动化治理能力。系统采用“软监控 (Soft Audit)”模式，即通过异步扫描和统计提供决策支持，而不实时拦截用户的业务流程，从而兼顾运维效率与系统性能。

## 2. 核心功能 (Core Features)

### 2.1 资源概览看板 (Storage Dashboard)
*   **全局存储分布**: 统计并展示下载目录、上传目录、插件目录及数据库的整体占用情况。
*   **TOP 占用排行榜**: 列出存储占用量前 10 名的用户，支持点击跳转到用户详情。
*   **文件类型统计**: 按视频、音频、文档、压缩包等类别统计文件数量与体积。
*   **趋势分析**: 展示过去 30 天存储总量的增长趋势。

### 2.2 软监控与配额管理 (Soft Audit & Quota)
*   **配额设定**: 管理员可为特定用户或角色设定“软配额”（如 50GB）。
*   **超额预警**: 系统扫描发现用户超额后，在 GM 用户列表和治理页面标记为“红色预警”状态。
*   **状态审计**: 记录用户触发配额预警的时间点，供运维分析。

### 2.3 自动化治理策略 (Policy Engine)
*   **过期清理策略**:
    *   自动删除已过期且超过 X 天的分享文件。
    *   自动清理已完成且超过 Y 天的下载任务记录（可选是否保留物理文件）。
*   **临时文件回收**:
    *   自动清理超过 24 小时未更新的 `.part` 临时文件。
*   **执行计划**: 集成至 `node-cron` 调度器，支持管理员自定义执行周期（如每日凌晨 3 点）。

### 2.4 运维工具箱 (Manual Toolbox)
*   **即时扫描**: 手动触发全盘资源统计任务。
*   **紧急清理**: 一键清空特定用户的临时文件夹。
*   **孤儿文件探测**: 扫描磁盘中存在但数据库无记录的“幽灵文件”并支持清理。

## 3. 技术架构 (Technical Architecture)

### 3.1 后端实现 (Backend)
*   **Service 层**: 新增 `ResourceService` 负责文件系统遍历 (`fs.stat`) 和数据库聚合查询 (`SUM`)。
*   **存储层**:
    *   新增 `StorageStats` 表存储每日统计快照。
    *   使用 `AppSetting` 存储治理策略配置（JSON 格式）。
*   **任务层**: 在 `schedule-executor.service.ts` 中注册资源治理相关的定时任务。

### 3.2 前端实现 (Frontend)
*   **页面**: `apps/gm-admin/src/pages/GovernancePage.tsx`。
*   **组件**: 使用 `recharts` 或原生 CSS 进度条展示存储分布。
*   **交互**: 提供策略编辑表单和手动执行按钮。

### 3.3 共享层 (Shared)
*   **Schema**: 在 `@dm/shared` 中定义 `GmStorageStatsResponse` 和 `GmResourcePolicy` 的 Zod 校验器。

## 4. 数据一致性与性能 (Consistency & Performance)
*   **异步扫描**: 所有资源统计任务均在后台运行，严禁在 API 请求路径中同步执行大范围文件扫描。
*   **缓存机制**: 前端获取的统计数据基于最近一次扫描的快照，支持秒级响应。
*   **安全性**: 资源治理 API 仅限 GM 角色访问，所有清理操作必须记录在 `Activity` 审计日志中。
