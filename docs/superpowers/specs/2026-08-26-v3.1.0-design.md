## 1. 目标与范围

### 1.1 版本定位

综合性版本：在 v3.0.0 monorepo 基础上，兼顾"体验闭环 / 技术债清理 / 运维设施补齐 / 未来地基"四个方向，在 3-4 周内完成。

### 1.2 范围概览

| 子项 | 范围 | 估时 | 风险 |
|---|---|---|---|
| S1 桌面 Onboarding | 4 步向导 + first-run 检测 + Electron 集成 | 3-4 天 | 低 |
| S2 技术债清理 | ESLint 清零 / React19 弃用 / Redis 移除 / 子项目一致性 | 4-5 天 | 低 |
| S3 运维设施补齐 | GM 后台 MVP / OpenAPI 刷新 / seed 修复 / db 备份导入 | 5-6 天 | 中 |
| S4 插件系统 RFC + MVP | 全量 RFC 5 份 + hello-world 可运行插件 | 6-8 天 | 高 |

### 1.3 推进路径（方案 B 并行+集成）

- **W1**：S2（技术债）+ S3（运维设施）并行启动。两者不冲突（S2 是代码改造，S3 是脚本/文档/GM 后台）。
- **W2**：S1 桌面 Onboarding 独立 sprint，依赖 S2 部分成果（子项目一致性）。
- **W3-W4**：S4 插件系统 RFC + MVP，最复杂的工作放最后专注完成。

### 1.4 非目标（推到 v3.2.0+）

- 下载协议扩展（BT/磁链/FTP/流媒体/ytdlp 集成）
- AI 智能化（推荐调度/自动分类/智能重试）
- 插件市场前端 UI（v3.1.0 仅做 API 草案 + 后端接口骨架）
- 分布式下载（P2P/多节点协同）

### 2.2 架构原则

1. **不破坏 v3.0.0 契约**：API 信封 `{ success, data/error, timestamp }` 保持，Zod schema 只新增不修改字段。
2. **新增模块默认可选**：插件系统、GM 后台、Onboarding 都用 feature flag 控制，关闭不影响主流程。
3. **SDK 与宿主分离**：`packages/plugin-sdk` 不依赖 Express/Prisma，仅导出类型与工具，可独立 `npm publish`。
4. **S3 与 S4 边界**：S3 的 GM 后台是"管理已运行系统"，S4 的插件市场是"扩展系统能力"，两者通过 `packages/plugin-sdk` 复用权限模型。

### 2.3 依赖关系图

```

   └── packages/plugin-sdk (UI 插件类型)

   └── packages/plugin-sdk (作者侧依赖)
```

## 3. §2 桌面 Onboarding

### 3.1 First-run 检测

```ts
// apps/desktop/src/first-run.ts
const USER_DATA = app.getPath('userData'); // %APPDATA%/download-manager
const SENTINEL = path.join(USER_DATA, '.onboarded');

async function isFirstRun(): Promise<boolean> {
  if (await fs.pathExists(SENTINEL)) return false;
  // 双保险：DB 中 users 表为空也算首次
  const userCount = await safeCountUsers();
  return userCount === 0;
}

async function markOnboarded() {
  await fs.writeFile(SENTINEL, new Date().toISOString());
}
```

哨兵文件 + users 表为空双重判定，避免任一信号丢失导致向导反复弹出。

### 3.2 4 步向导 UI

| Step | 标题 | 内容 | 校验/调用 |
|---|---|---|---|
| 1 | 欢迎 | 应用介绍 + "跳过向导" + "继续 →" | 跳过：写哨兵 + 创建默认 admin/Admin@123 + 主界面顶部提示条 |
| 2 | 创建管理员账号 | username/email/password/confirm | Zod 实时校验 + POST /auth/setup |
| 3 | 设置下载目录 | downloadDir + maxConcurrent + speedLimitKBps | Electron showOpenDialog + 写权限测试 |
| 4 | 完成 | ✓ 管理员 ✓ 下载目录 ✓ 数据库 | 写 .onboarded 哨兵 + 跳转 /downloads |

### 3.3 状态机

```
[启动 Electron]
       │
       ▼
[first-run 检测] ─── 否 ──→ [直接加载主界面]
       │ 是
       ▼
[加载 /onboarding 路由]
       │
       ▼
[Step 1] ⇄ [Step 2] ⇄ [Step 3] ⇄ [Step 4]
   │             │             │
   │             │             │ (IPC 选择目录)
   │             │ (POST /auth/setup)
   │             │ (bcrypt hash + DB insert)
   │             ▼
   │             [失败重试本步]
   │
   ▼
[写 .onboarded 哨兵]
       │
       ▼
[路由跳转 /downloads]
```

### 3.4 数据契约

```ts
// packages/shared/src/schemas/onboarding.ts
export const OnboardingStep2Schema = z.object({
  username: z.string().min(3).max(20).regex(/^[a-zA-Z0-9_]+$/),
  email: z.string().email(),
  password: z.string().min(8).max(128),
});

export const OnboardingStep3Schema = z.object({
  downloadDir: z.string().min(1),
  maxConcurrent: z.number().int().min(1).max(10).default(5),
  speedLimitKBps: z.number().int().min(0).default(0),
});
```

新 API: `POST /auth/setup`
- 仅首次可用（后端校验 users 表为空）
- 请求体: `OnboardingStep2Schema`
- 响应: `{ success, data: { token, user } }`
- 错误: `409` if users 表非空（已 onboarded）

### 3.5 错误处理

- **目录无写权限**：Step 3 测试写入 → 提示"该目录不可写，请选择其他位置"
- **密码弱**：实时强度条 + Zod 校验，弱密码禁用"继续"按钮
- **MariaDB 启动失败**：Step 4 前检查后端 /health，失败显示重试按钮（不阻塞向导）
- **用户中途关闭**：不写哨兵文件，下次启动仍进入向导，已完成的步骤不保留
- **跳过向导**：写入 .onboarded + 创建默认 admin/Admin@123，主界面顶部显示"建议修改默认密码"提示条

## 4. §3 技术债清理

### 4.1 S2.1 ESLint 警告清零

**第一步**：在所有 5 个 workspace（api/web/desktop/gm-admin/packages）跑 `pnpm -r lint` 取准确基线。v3.0.0 历史快照显示 24 条警告、综合审查又记录 ~249 条，存在不一致，需重新测量。

| 规则类别 | 典型来源 | 修复策略 |
|---|---|---|
| `exhaustive-deps` | SearchFilter / AIAssistant 等 useEffect | 补依赖或拆 effect，禁用 `eslint-disable` |
| `no-array-index-key` | 列表渲染 `.map((x,i) => ... key={i})` | 改用 stable id（item.id 或 hash） |
| `no-unused-vars` | 死代码 | 删除，不使用 `_` 前缀绕过 |
| `@typescript-eslint/*` | 类型断言 any | 补类型或 narrowing |

**门禁**：CI 加 `pnpm -r lint -- --max-warnings=0`，PR 触发 lint 失败。

### 4.2 S2.2 React 19 弃用项

| 弃用 API | 替代 | 影响范围 |
|---|---|---|
| `forwardRef` + `{ forwardRef }` | 直接 `ref` prop（React 19 ref as prop） | shadcn Button/Input/...、自定义 SearchFilter |
| `useContext(Context)` | `use(Context)`（条件渲染场景） | Toast、notificationService、searchHistoryService 等 |
| `propTypes`/`defaultProps` | TS 类型 + 默认值在解构 | 扫描所有 .tsx |

v3.0.0 已部分迁移，需 `grep -r "forwardRef\|useContext\|defaultProps" apps/web/src` 确认残留（仅返回 SDK 类型为合格）。

### 4.3 S2.3 移除 Redis 依赖

v3.0.0 中 Redis 标记为可选，实际未启用。v3.1.0 决定移除（YAGNI）。

```ts
// apps/api/src/services/cache.service.ts 替代实现
class MemoryCache<K, V> {
  private store = new Map<K, { v: V; exp: number }>();
  get(k: K) {
    const e = this.store.get(k);
    if (!e) return undefined;
    if (e.exp < Date.now()) { this.store.delete(k); return undefined; }
    return e.v;
  }
  set(k: K, v: V, ttlMs: number) { this.store.set(k, { v, exp: Date.now() + ttlMs }); }
  del(k: K) { this.store.delete(k); }
}
```

**改造范围**：

- `apps/api/src/config/redis.js` → 删除
- `apps/api/src/services/cache.service.ts` → 切换到 MemoryCache（接口不变，调用方 0 改动）
- `apps/api/package.json` → 移除 `ioredis` 依赖
- `apps/api/.env.example` → 删除 `REDIS_*` 字段
- `docker-compose.yml` → 删除 redis 服务
- `README.md` → 删除 Redis 说明

### 5.3 S3.3 测试账号管理修复

v3.0.0 末已修复硬编码密码（seed.ts 读 env），但仍有问题：upsert update 为空 → 已存在的账号不会更新密码；缺 db:reset 脚本。

```ts
// apps/api/prisma/seed.ts 改造
async function upsertUser(email, username, password) {
  const hashed = await bcrypt.hash(password, 10);
  // 关键：update 包含 password 字段（仅在显式调用 seed 时覆盖）
  await prisma.user.upsert({
    where: { email },
    create: { email, username, password: hashed, role: ... },
    update: { password: hashed, updatedAt: new Date() },
  });
}

// 新增 apps/api/scripts/db-reset.ts
import { execSync } from 'child_process';
async function main() {
  // 警告确认
  const ans = await prompt('This will DROP all data. Type "yes": ');
  if (ans !== 'yes') process.exit(1);
  execSync('pnpm prisma migrate reset --force', { stdio: 'inherit' });
  execSync('pnpm prisma:seed', { stdio: 'inherit' });
  console.log('✓ Database reset complete');
}
```

**新增脚本**：

- `db:reset` → `tsx scripts/db-reset.ts`
- `db:seed:gm` → `tsx scripts/seed-gm.ts`
- `db:seed:admin-only` → `tsx scripts/seed.ts --only=admin`

**安全**：seed.ts 仅在 `NODE_ENV !== 'production'` 时运行，避免生产环境账号被覆盖。

### 5.4 S3.4 数据库备份与导入

提供 CLI 脚本用于开发/小规模部署的数据迁移。大规模生产建议用 mysqldump 直接做。

```ts
// apps/api/scripts/db-export.ts
import { execSync } from 'child_process';
async function main() {
  const ts = new Date().toISOString().replace(/[:.]/g, '-').slice(0, -5);
  const out = process.env.OUT || `backup-${ts}.sql.gz`;
  execSync(`mysqldump -u ${USER} -p${PASS} -h ${HOST} ${DB} | gzip > ${out}`);
  console.log(`✓ Exported to ${out}`);
}

// apps/api/scripts/db-import.ts
async function main() {
  const file = process.argv[2];
  if (!file) throw new Error('Usage: db-import <backup.sql.gz>');
  execSync(`gunzip < ${file} | mysql -u ${USER} -p${PASS} -h ${HOST} ${DB}`);
  console.log(`✓ Imported ${file}`);
}
```

**新增脚本**：

- `db:export` → `tsx scripts/db-export.ts`
- `db:import` → `tsx scripts/db-import.ts`

**依赖**：系统 mysqldump / mysql 客户端；桌面应用打包时通过 mariadb-bin 自带。

## 6. §5 插件系统 RFC + MVP

### 6.1 三类插件接口

```ts
// packages/plugin-sdk/src/types.ts

export interface PluginManifest {
  id: string;            // 全局唯一，与 npm 包名解耦
  name: string;
  version: string;
  author: string;
  description: string;
  type: 'download-adapter' | 'script' | 'ui';
  permissions: Permission[];  // 声明式权限
  entry: string;              // 入口文件（相对插件根）
}

// 1. 下载协议适配器（如 magnet/http-stream/ftp/ytdlp）
export interface DownloadAdapter {
  canHandle(url: URL): boolean;
  createTask(url: URL, opts: DownloadOpts): Promise<DownloadTask>;
  onProgress(taskId: string, cb: (p: Progress) => void): Unsubscribe;
  pause(taskId: string): Promise<void>;
  resume(taskId: string): Promise<void>;
  cancel(taskId: string): Promise<void>;
}

// 2. 脚本插件（事件触发，如下载完成后调脚本）
export interface ScriptPlugin {
  hooks: Partial<{
    onDownloadStart(ctx: DownloadContext): Promise<void>;
    onDownloadComplete(ctx: DownloadContext): Promise<void>;
    onDownloadError(ctx: DownloadContext, err: Error): Promise<void>;
    onFileSaved(ctx: FileContext): Promise<void>;
    onSchedule(ctx: ScheduleContext): Promise<void>;
  }>;
}

// 3. UI 插件：通过 PluginContext 提供的命令式注册器注入主界面
//    （registerMenu/registerPage/registerWidget 在 ctx 中由 PluginHost 注入）
export interface UIPlugin {
  // 可选的静态声明：插件可在此返回初始贡献，等价于 activate 中手动注册
  readonly contributions?: {
    menus?: MenuContribution[];
    pages?: PageContribution[];
    widgets?: WidgetContribution[];
  };
}

// 插件生命周期接口：所有插件必须实现
export interface PluginLifecycle<TCtx = PluginContext> {
  activate(ctx: TCtx): Promise<void> | void;
  deactivate(ctx: TCtx): Promise<void> | void;
}

// 复合类型：插件作者 default 导出此类型
export type Plugin<TType extends PluginManifest['type']> =
  PluginLifecycle<PluginContext<TType>> &
  (TType extends 'download-adapter' ? DownloadAdapter :
   TType extends 'script' ? ScriptPlugin :
   TType extends 'ui' ? UIPlugin : never);

// PluginContext 由 PluginHost 在 activate 时传入，含 host API + 注册器
export interface PluginContext<TType extends PluginManifest['type'] = 'ui'> {
  host: HostAPI;            // logger / showNotification / emit / on
  registerMenu: (m: MenuContribution) => void;
  registerPage: (p: PageContribution) => void;
  registerWidget: (w: WidgetContribution) => void;
  manifest: PluginManifest;
}
```

### 6.2 沙箱选型

| 方案 | 隔离强度 | 性能 | 维护 | 复杂度 |
|---|---|---|---|---|
| vm2 | 高 | 中 | 已废弃 | 低 |
| isolated-vm | 极高 | 高（V8 isolate） | 活跃 | 高（C++ addon） |
| **worker_threads** + 进程隔离 | 中 | 高 | 原生 | 中 |

**选定 worker_threads**：原生无原生依赖、Electron 已支持、性能足够。下载协议适配器跑在 Worker，UI 插件直接在主 React 进程（受 CSP 限制）。

### 6.3 权限模型

```ts
// packages/plugin-sdk/src/permissions.ts
export type Permission =
  | { type: 'network'; hosts: string[] }   // 允许访问的域名白名单
  | { type: 'fs'; paths: string[]; mode: 'r'|'w'|'rw' }  // 文件系统
  | { type: 'env'; keys: string[] }        // 环境变量
  | { type: 'spawn'; commands: string[] } // 子进程（如 ytdlp）
  | { type: 'ui'; inject: ('menu'|'page'|'widget')[] }
  | { type: 'api'; endpoints: string[] };  // 调用宿主 API
```

宿主侧 `PluginHost` 在 Worker 启动时 inject 受限的 require/fetch：

```ts
const sandbox = {
  fetch: makeScopedFetch(manifest.permissions),  // 仅白名单域名
  fs: makeScopedFs(manifest.permissions),        // 仅白名单路径
  require: makeScopedRequire(manifest.permissions),
  host: makeHostAPI(manifest.permissions),       // 调用宿主 API（受 manifest 限制）
};
```

**用户授权流程**：安装时用户在 UI 看到 `manifest.permissions` → 同意后写入 `plugins/installed.json`。

### 6.4 生命周期事件

```
[安装] ─→ 验证签名 ─→ 解压到 plugins/<id>/ ─→ 加载 manifest ─→ 用户授权 ─→ 注册
   │                                                      │
   │                                                      ▼ 拒绝
   │                                                  [回滚 + 提示]
   ▼
[启动宿主] ─→ 扫描 installed.json ─→ 为每个插件 fork Worker ─→ 调用 plugin.activate(ctx)
   │
   ▼
[事件触发] ─→ host.emit('download:start', ctx) ─→ Worker 内广播 ─→ script hook 执行
   │
   ▼
[卸载] ─→ 调用 plugin.deactivate(ctx) ─→ 关闭 Worker ─→ 删 plugins/<id>/ ─→ 移除 installed.json
```

### 6.5 插件市场 API 草案

v3.1.0 仅做 API 设计，不实现前端市场页。


### 6.6 hello-world MVP 插件

```js
// plugins/hello-world/manifest.json
{
  "id": "hello-world",
  "name": "Hello World",
  "version": "1.0.0",
  "author": "dm-team",
  "description": "Demo plugin: adds a menu item + listens to download events",
  "type": "ui",
  "permissions": [
    { "type": "ui", "inject": ["menu"] }
  ],
  "entry": "index.js"
}

// plugins/hello-world/index.js
export function activate(ctx) {
  ctx.host.logger.info('Hello World plugin activated');

  ctx.registerMenu({
    id: 'hello-world.greet',
    label: 'Say Hello',
    onClick: () => ctx.host.showNotification('Hello from plugin!'),
  });

  ctx.host.on('download:complete', (event) => {
    ctx.host.logger.info(`Download finished: ${event.filename}`);
  });
}

export function deactivate(ctx) {
  ctx.host.logger.info('Hello World deactivated');
}
```

**验收路径**：启动 → 主界面看到"Say Hello"菜单 → 点击看到通知 → 触发下载完成事件后看日志。
